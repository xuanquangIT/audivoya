# Deploy the website

Every merge into `main` publishes https://xuanquangit.github.io/audivoya/. That makes merging a **Deploy-class** action (AGENTS.md → Autonomy policy): do it when the request asks to deploy, publish, release or ship, then report. Without such a request stop at "ready to deploy" ([site-ship](../site-ship/SKILL.md)). The store-listing check (§5) is read-only and always allowed.

Commands are POSIX shell (Git Bash on Windows). `<n>` is the PR number.

## 1. Preconditions

```sh
gh pr view <n> --json number,title,isDraft,baseRefName,headRefName,headRefOid,mergeStateStatus,statusCheckRollup,body
```

| `mergeStateStatus` | Meaning                                              | Do                                                                                  |
| ------------------ | ---------------------------------------------------- | ----------------------------------------------------------------------------------- |
| `CLEAN`            | `verify` green on the latest `main`                  | Merge (§2)                                                                          |
| `BEHIND`           | Strict check: `main` moved                           | Rebase loop in site-ship §7, wait for `verify`, re-check                            |
| `DIRTY`            | Conflicts                                            | Rebase and resolve (site-ship §7)                                                   |
| `BLOCKED`          | `verify` failing/pending or unresolved conversations | Fix the check; reply to and resolve review threads                                  |
| `UNSTABLE`         | A non-required check failed                          | Read it (`gh pr checks <n>`); merge only if it is unrelated and explained in the PR |
| `isDraft: true`    | Not ready                                            | `gh pr ready <n>` only if the work is complete                                      |

Content gates before merging:

- [ ] Base is `main`; title is a Conventional Commit (it becomes the squash subject with ` (#<n>)`).
- [ ] PR body has the Evidence table with NOT RUN where not run.
- [ ] Ordering constraints in the Deploy section hold. "Publish only after <x.y.z> is live" → run §5 now and stop if the listing does not show it. Release-sync Phase A → the extension release PR must not have merged yet, or the privacy update is late; report that.

## 2. Merge at the verified head

```sh
HEAD_SHA="$(gh pr view <n> --json headRefOid -q .headRefOid)"
gh pr merge <n> --squash --match-head-commit "$HEAD_SHA"
git push origin --delete "$(gh pr view <n> --json headRefName -q .headRefName)" || true
```

Do not pass `--delete-branch` from a worktree: gh then tries to switch the worktree to `main`, which the main checkout already holds. `git push origin --delete` of a non-protected branch is fine; it fails harmlessly when GitHub already deleted it. Never push to `main` directly.

## 3. Watch the Pages run

```sh
git fetch origin
MAIN_SHA="$(git rev-parse origin/main)"
gh run list --workflow pages.yml --branch main --event push --commit "$MAIN_SHA" --json databaseId,status,conclusion,url
gh run watch <databaseId> --exit-status
```

- Empty list: the run has not registered yet; list again after about 10 s.
- `cancelled`: a newer push to `main` superseded it (concurrency `pages-refs/heads/main`, cancel-in-progress). Fetch again and watch the run for the new `origin/main`; it deploys your change too.
- Failure: `gh run view <databaseId> --log-failed`. Transient infrastructure (gitleaks download, `npx playwright install`, Pages API 5xx) → `gh run rerun <databaseId> --failed`; re-running is part of this approved deploy. Code failure → fix forward with a new PR (site-ship).
- Success means both jobs passed: `gh run view <databaseId> --json jobs -q '.jobs[] | [.name, .conclusion] | @tsv'` shows `verify success` and `deploy success`.

## 4. Verify the live site

Build exactly what `main` deployed. Use the main checkout (post-deploy checks are integration work):

```sh
SITE_MAIN="$(dirname "$(git rev-parse --path-format=absolute --git-common-dir)")"
cd "$SITE_MAIN"
git status --short --branch             # expect "## main...origin/main" and no changes
git pull --ff-only origin main
git diff --quiet ORIG_HEAD HEAD -- package-lock.json || npm ci --ignore-scripts
npm run build
node scripts/verify-live.mjs
```

If the main checkout is dirty or on another branch, do not touch it: run the same build and check in the merged task worktree after `git switch --detach origin/main` (and `node scripts/worktree/setup.mjs --install` if the lockfile changed), then remove that worktree by path in §7.

It fetches every `dist/` file from production and compares SHA-256, then loads the 5 routes at 1440, 390 and 320 px (15 page checks): HTTP 200, visible `h1`, no horizontal overflow, images loaded, no external requests. Output: one JSON line, `artifacts/live-verification.json`, `artifacts/live-home-{1440,390,320}.png` — open the screenshots.

| Failure                                           | Cause                                                                              | Do                                                                        |
| ------------------------------------------------- | ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `Deployed content differs: <file>`                | CDN still serves the old file (up to ~10 min) or `dist/` is not from `origin/main` | Confirm `git rev-parse HEAD` = deployed SHA; retry every 2 min for 10 min |
| `Public resource unavailable: <file>` (404)       | Deploy missing or still propagating                                                | Check the deploy job; retry as above                                      |
| `Horizontal overflow: <route>` / external request | Real regression that CI did not catch                                              | Fix forward (`fix/` PR); record the gap                                   |
| Persisting mismatch after 10 min                  | Deploy did not run or failed silently                                              | `gh workflow run pages.yml --ref main` (Deploy class) and watch it        |

## 5. Store listings (anonymous)

Fresh browser, no profile, no sign-in; run from a site checkout:

```sh
node --input-type=module <<'EOF'
import { chromium } from '@playwright/test';
import { site } from './site.config.mjs';
const browser = await chromium.launch();
try {
  for (const [store, url] of Object.entries(site.stores)) {
    const page = await browser.newPage();
    const response = await page.goto(url, { waitUntil: 'domcontentloaded', timeout: 45000 });
    await page.getByText(/Version/).first().waitFor({ timeout: 20000 }).catch(() => {});
    const text = await page.locator('body').innerText();
    const version = text.match(/Version\s*:?\s*(\d+(?:\.\d+){1,3})/)?.[1] ?? 'not shown';
    console.log(JSON.stringify({ store, status: response?.status(), url: page.url(), version }));
    await page.close();
  }
} finally {
  await browser.close();
}
EOF
```

Expect `status` 200, `url` on `chromewebstore.google.com/detail/…/epkhkijhmdajkhaedfdncdoaafdhnhlk` and `microsoftedge.microsoft.com/addons/detail/…/ijcfkaioapolmcgmkhgaadhchiakhkeb`, and the version you are about to claim. For a listing not yet in `site.config.mjs`, replace `Object.entries(site.stores)` with `[['<store>', '<url>']]`. `version: 'not shown'` is not proof: retry once, then record it as unverified and do not claim the version.

## 6. Record

The deploy record goes on the PR (a `docs/VALIDATION.md` commit now would trigger another deploy):

```sh
gh pr comment <n> --body "Deployed $MAIN_SHA via <run url>. verify-live: <JSON line>. Screenshots reviewed: 1440/390/320. Store listings: <JSON lines or NOT RUN>."
```

The next content PR may cite this comment in its validation entry. Report the same summary to the user.

## 7. Clean up

```sh
cd "$SITE_MAIN" && node scripts/worktree/wt.mjs prune --merged
node scripts/worktree/wt.mjs rm <worktree path> && git branch -D <type>/<slug>   # only for a worktree you detached in §4
```

Run them from the main checkout: prune skips the current worktree, dirty worktrees and protected branches.

## Roll back

Fix forward. For a bad deploy: `node scripts/worktree/wt.mjs new fix/revert-<slug>`, `git revert --no-edit <squash sha>`, then site-ship and this skill. Never force-push or reset `main`.

## Done when

- [ ] PR squash-merged at the head SHA that passed `verify`.
- [ ] Pages run for the final `origin/main` succeeded (`verify` and `deploy`).
- [ ] `verify-live.mjs` passed (files matched, 15 page checks, 0 external requests) and its screenshots were reviewed.
- [ ] Store listings checked when the PR changed version or availability copy.
- [ ] PR comment posted; merged worktree and branches removed.
